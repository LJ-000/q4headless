Step 2 · Where do your customers work?

Where it lands

Inside Salesforce, where your customer already works.

  • Register your external MCP server so Agentforce can call it as an MCP client.
  • Package an Agentforce agent and actions, so your logic becomes tools.
  • Build UI with LWC and Lightning types, or with Multi-Framework.

Where to start

  • External MCP Registration
  • Agentforce scripts and actions
  • Multi-Framework UI

Where it lands

On the surface where your customer already works, with Salesforce context behind it.

  • Let outside agents reach the org through the Headless MCP Server and an External Client App.
  • Render widgets natively from one configuration: a Block Kit card in Slack, an adaptive card in Teams.
  • Use marketplace connectors so customers set up access with a click.

Where to start

  • Headless MCP Server via ECA
  • HXL widgets
  • Skills and plugins

If your customers are not on Salesforce

Embed partners (OEM)

You run your own branded product on top of Salesforce, with Salesforce invisible underneath. OEM solutions rely on Platform licenses with access limited to a small set of objects, and most of your customers aren’t existing Salesforce customers. Cloud-specific objects have been out of reach. A few select OEM partners can use approved objects.

Back to headless. Headless lets you ship AI-native features under your own brand.

Your build plan

From architecture to AgentExchange.

Five steps to get a headless capability in front of customers.

  1. 1

    Architect

    Pick your starting point and where your customers work. Choose a pattern from the table above, and decide which capabilities agents should call.

  2. 2

    Build

    Expose your logic as agent tools: an MCP server, or Apex, Flows and named queries. Add HXL widgets or a Multi-Framework UI where the experience needs one.

  3. 3

    Package

    Package Apex, Flows and named queries, with an External Client App if you need one. MCP packaging is still changing, so check current guidance before you commit.

  4. 4

    Test

    Test with per-user auth and ECA scoping, then go through Security Review.

    Security Review
  5. 5

    Distribute

    List on AgentExchange: review, discovery, procurement, telemetry, joint selling and partner programs.

Capabilities and status change. Check current status before you build.
